## How to work (read once)

**Read first, every time:** `.claude/skills/marketing-messaging/SKILL.md`, `.claude/skills/marketing-page-design/SKILL.md`, `.claude/skills/seo-strategy/SKILL.md`, `docs/marketing/site-profile.md`. The profile wins where it is stricter than a skill.

**House rules for every word that ships:**
- British English. Reading age about 9 (10 or under on the checker). Average sentence 12 words or fewer, none over 20.
- No em or en dashes, no spaced hyphens used as dashes, no exclamation marks, no curly quotes typed into code.
- None of the banned hype words (list in the messaging skill), no "not just X, it's Y", no stacked "No X. No Y. No Z.", no question followed by a one-word answer, no triads for rhythm.
- Never mention teams, staff, juniors, developers on our side, "agency of one" or "full-service agency". Talk about the experience: "you deal with the same person".
- **No jargon, ever** (Sean). The banned list is in the site profile, section 2: no "Core Web Vitals", "INP", "schema", "information architecture", "tech stack", "headless" and the like. Say what it does for the owner.
- **Never name the technology** that makes sites fast and easy to edit (React, Sanity and similar) in public copy. Say "you can edit your own pages and blog easily".
- **Show, don't score.** Owners lean in when they see a fast, clean result or a feature they did not know they could have. Lead with real before-and-afters; keep speed scores out of headlines.
- **The main doubt to answer first:** "we paid a lot last time and it was still bad". Then: "will I have to learn a new system?"
- Never invent numbers, quotes, logos or results. Facts that are confirmed are in the site profile, section 3. Midland Oil: more than 8 seconds before, 1.2 seconds after, three times the enquiries in the first month. The "#1" ranking claims carry "Checked October 2026" and never name the search terms.

**Where things live:**
- Page code: `src/pages/**`, homepage sections in `src/components/homepage/*.astro`, React parts in `client/components/**`, layouts in `src/layouts/*`.
- Page titles and descriptions: Sanity overrides the code. Edit `apps/studio/sanity/seeds/page-route-starters.ndjson` (and `client/lib/seo.ts` and the page's `title`/`description` props to match), then run `pnpm sync:seo:fields` to preview and `pnpm sync:seo:fields -- --apply` to write. This needs a Sanity login (`pnpm exec sanity login`, done in a browser by Sean) or `SANITY_API_TOKEN` in `.env`.
- Blog posts and their SEO fields: Sanity Studio at `/studio/` (post documents). Not in the repo.
- Untitled UI components: add to `client/components/untitled/` (see F-01). Do not touch `client/components/ui/` (shadcn, used by the builder app).

**Checks before you commit (all must pass):**
1. `pnpm exec tsc --noEmit -p .` and `pnpm exec astro check`.
2. `KAIZEN_DEPLOY_BRANCH=main pnpm run build` (the server's build command).
3. House style on what you changed: `node scripts/audit/house-style.mjs --dist dist /your/page/` (Git Bash on Windows: prefix `MSYS_NO_PATHCONV=1`). Zero hard-rule breaches; reading age and sentence targets met for marketing pages.
4. Screenshots at 1440px and 375px: run the dev server (`pnpm exec astro dev --port 4321`), then `BASE_URL=http://localhost:4321 node scripts/audit/page-shots.mjs <outDir> /your/page/`. Look at every tile. No horizontal overflow, nothing overlapping, no empty or unfinished band.
5. If you touched shared code (layouts, `shared/`, `client/visual-builder/`): `pnpm exec vitest --run`. Baseline on this Windows machine after the 1 Oct dependency upgrade (`10b91b5`): 1,540 tests, 1,084 pass, 438 fail. The failures are builder server tests that need Linux (deployment, hosted, native, release, upload and domain specs). Every test that passed before must still pass; save `--reporter=json` output before and after and compare by test name.

**Shipping:** commit to `main` and push; that deploys production. Fast-forward `stage` to the same commit (`git push origin HEAD:stage`) so the builder's publish flow stays valid. If a deploy fails at "Activate public release", re-run it (`gh run rerun <id> --failed`). Log anything that affects search in `docs/seo-log.md` (date, URL, what changed). Check the live page after the deploy.

**Do not:** upgrade TypeScript past 6.x (the builder calls its compiler API at runtime); change URLs for a keyword; add statistics without a primary source; add client logos or quotes without written permission; publish `/studio/` or builder changes from these tasks.

**Definition of done for any page task (copy the list into the commit message or task note):**
- [ ] First screen at 375px says what Kaizen does, who it is for, and the next step.
- [ ] Headings alone tell the argument (spoilers, not "FAQ" or "What we do").

- [ ] Title, description and H1 follow the SEO rules; text is in the server HTML (no click-to-load content).
