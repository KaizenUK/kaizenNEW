# P-06: show what the website speed check gives you

Prepared 2 October 2026 from the task board, site profile, Q-01 proof, B-02 report guide and current page/scanner source. Implemented and verified in `5c1fb06`; the real sample and production checks are recorded in `docs/audits/2026-10-02-p06-proof.md`.

## Reader and message order

An owner has a website that feels slow and wants a useful place to start. Put the web-address input near the first explanation, show what the resulting report actually looks like and explain what to do with it.

1. Check how one page loads in a simulated phone visit.
2. See the score first. Below 90, enter an email address to reveal the full report; marketing tips remain optional.
3. Download the report in the browser. It is not emailed.
4. Use the findings to decide what needs a closer look. The score does not measure lost enquiries or promise search positions.
5. Read the existing guide or ask for help with the site. The first conversation is free; work follows an agreed scope and non-refundable deposit.

The page owns website speed testing in S-01. It should serve that job before introducing the paid website service. Keep its URL and search metadata unless evidence requires a correction.

## Design direction

The current hero is a long text block followed by Free/Mobile/PDF facts; the input appears in a later dark band. Show the useful action earlier and put the real sample beside or directly after it. On a phone, keep the explanation, address field and honest email note together before a compact sample. The sample must remain legible, with its full image available if needed; avoid an unreadably tiny full PDF page.

Use the released F button, FAQ, type, spacing and navigation foundations. This task can use a tool-specific input/result composition without copying the homepage's bespoke hero or buyer-route patterns, which still await Sean's review. No invented product controls, decorative scores or unearned results.

The source currently explains the three available test measures in plain language. Keep that approach: the profile's no-jargon rule wins over the board's older suggested technical heading. Do not claim that this tool measures every real visitor's experience.
