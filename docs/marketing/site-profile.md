## 2. House voice

- Plain English. **No jargon, ever (Sean, 1 Oct 2026)**: not on pages, headings, buttons or FAQs. Say what it does for the owner. Words to remove where they appear: tech stack, monolithic, Core Web Vitals, LCP, INP, CLS, Cumulative Layout Shift, Lighthouse, information architecture, crawl budget, schema, data markup, structured data, decoupled, headless, frontend, render, cache, plugin soup. Confident but approachable (`CLAUDE.md`).
- **Never name the technology** that makes fast sites easy to edit (for example React with Sanity), anywhere in public copy (Sean: "people will copy us"). Say what the owner gets: "you can edit your own pages and blog easily". Tags like "React" and "Headless WordPress" come off case studies.
- **Show, don't score (Sean):** owners lean in when they see a fast, clean first draft or a feature they did not know they could have, not a speed score. Lead with real before-and-afters and results; keep scores out of headlines.
- The SUCCESS model applies to all copy: Simple, Unexpected, Concrete, Credible, Emotional, Stories (`CLAUDE.md`, from `guidance/Viral_Content_Guide.pdf`). How it fits the method: `marketing-messaging`, "How this fits the SUCCESS model".
- Default Kaizen voice rules from `marketing-messaging` apply unless Sean says otherwise: reading age about nine, British spelling, no em dashes, no hype words, no exclamation marks, must never read as AI-written.
- **Never** mention teams, juniors, seniors, developers or any staffing structure, and never imply either a team or a solo setup. One agreed exception (Sean, 1 Oct 2026): the line under the main button says "one of us" will get back to you, and never names Sean personally. Talk about the experience the customer gets ("you deal with the same person", consistency, no runaround). Existing headings already do this well: "One person. The whole way.", "Advice before invoices.", "Plain English. Every step."
